# Разработка, тесты и сборка

Готовый пользовательский архив и исходники Git решают разные задачи. Пользователю не нужны перечисленные ниже инструменты: он распаковывает Release и запускает `.command` или `Setup.cmd`.

## Каталоги

| Путь | Содержимое |
|---|---|
| `macos/app/` | Bash-запуск, запасная стартовая страница и локальная инструкция |
| `macos/extension/` | Бесплатное расширение 0.14.0 для Claude и Gemini |
| `macos/runtime-lock.json` | Точная версия, URL, размеры и SHA двух оригинальных браузеров |
| `macos/tests/` | Проверки сервисов, сравнения, экспорта, сценария запуска, интеграции и готовых ZIP |
| `windows/app/` | PowerShell-установщик и запуск сохранённой версии 0.13.1 |
| `windows/extension/` | Бесплатное расширение 0.13.1 для Claude |
| `docs/` | Описание версий, сборки и пределов проверок |

Каталоги браузерного кэша, временных тестовых профилей и реальные `Data/Profile` в Git не входят. Браузерные ZIP публикуются внутри готового комплекта в Releases, отдельно от дерева исходников.

## Зависимости разработчика

- Python 3.11+ для скриптов получения runtime и упаковки. Для последней локальной сборки использовался Python 3.13.
- Node.js с поддержкой `fs.readdirSync({recursive:true})`. Текущее проверенное окружение: Node.js 26.12.0.
- Playwright и подходящий тестовый Chrome for Testing. Внешние сервисы в тестах заменяются локальными ответами.
- Bash для проверки запуска; harness на Windows использует Git Bash.
- Для PowerShell-части — Windows 64 bit с Windows PowerShell и штатными .NET/WinForms.

Нативный запуск macOS-комплекта использует штатные `/bin/bash`, `ditto`, `shasum`, `codesign`, `open`, `plutil`, `PlistBuddy`, `sw_vers` и `sysctl`. Node.js и Python в готовый macOS-комплект не включаются и для его запуска не требуются.

## Runtime macOS

Используйте закреплённую совместимую версию из `runtime-lock.json`, сейчас `156.0.8078.47`:

```sh
python macos/fetch_runtime.py 156.0.8078.47
```

Скрипт сохраняет оригинальные ZIP в `macos/cache/156.0.8078.47/` и проверяет CRC, версию и архитектуру. `.app` на Windows не распаковывается: это сохраняет Unix-права и символические ссылки в оригинальном архиве. Готовый `.command` распаковывает payload на Mac через `ditto`.

Перед сборкой нужны обе платформы: `chrome-mac-arm64.zip` и `chrome-mac-x64.zip`. Их локальные пути указаны в поле `cachePath`; имена внутри готового payload остаются каноническими.

**Не запускайте получение runtime без явной версии для воспроизведения 0.14.0.** Этот режим запрашивает текущую Stable и может выбрать браузер, API которого ещё не совместим с расширением. В чистом клоне скрипт сам получает метаданные Stable для справки; скачиваемые браузерные ZIP при указанном аргументе остаются закреплены на 156.0.8078.47.

## Тесты

Быстрые проверки логики не запускают аккаунты и реальные страницы:

```sh
node macos/tests/extension.test.cjs
node macos/tests/comparison.test.cjs
```

Для тестов браузера установите зависимости разработчика командой `npm ci`. Playwright 1.62.1 закреплён в `package.json` и `package-lock.json`. Готовому пользовательскому комплекту эти зависимости не нужны.

```sh
node macos/tests/capture.test.cjs
node macos/tests/launcher.test.cjs
node macos/tests/integration.test.cjs
```

Параметры окружения:

| Переменная | Для чего нужна |
|---|---|
| `MINI_TEST_CHROME` | Путь к Chrome для DOM-проверок экспорта |
| `GIT_BASH` | Путь к Bash для Windows-harness запуска |
| `TEST_BROWSER` | Путь к Windows CfT для полной интеграции расширения |

Полная интеграция текущего скрипта — Windows-harness. Она создаёт собственный тестовый профиль и копию расширения, подменяет ответы сайтов локальными образцами и не использует реальные аккаунты. Специальный флаг для тестового вызова toolbar-action не входит в пользовательский запуск.

Симуляция `portable.sh` под Git Bash не подтверждает работу Finder, Gatekeeper, LaunchServices, Связки ключей или системной подписи на Mac. Для них предназначен отдельный ручной список внутри Release.

## Сборка macOS ZIP

Для сборки недостаточно скачать браузерные ZIP. Нужен успешный интеграционный отчёт **именно для закреплённой версии браузера**, соответствующий текущим хешам исходников расширения.

```sh
python macos/build.py
python macos/tests/final_delivery_review.py
```

Сборщик создаёт отдельные ZIP Apple Silicon и Intel. Каждый содержит один соответствующий оригинальный браузер, расширение, `.command`-запуск и инструкции; исследовательские инструменты, тестовый кэш и профили не включаются. Скрипт выставляет права исполнения 0755 для `.command`/Bash и сохраняет LF.

Публичный сборщик сопоставляет ключ расширения с `windows/extension/manifest.json`. Проверенный обезличенный отчёт находится в `docs/validation/macos/integration-tests.json`; его хеши сверяются с включёнными исходниками расширения. Локальные пути владельца, сырые CDP-цели и неиспользуемые старые файлы в этой публичной копии отчёта исключены, что отмечено внутри JSON. После изменений повторите интеграцию и подготовьте новый отчёт, соответствующий исходникам, вместо ручного изменения поля `passed`.

Отчёт о прошлой сборке подтверждает только ту сборку. После изменения кода или runtime тесты и хеши проверяются заново.

В `.gitattributes` отключено преобразование окончаний строк: Git сохраняет байты, по которым получены хеши. Включать автоматическое преобразование LF/CRLF для этих файлов не нужно.

## Windows 0.13.1

Здесь опубликованы сохранённые исходники Windows-комплекта, но не три его payload-архива. `Setup.cmd` из чистого клона не является готовым установщиком без них.

`windows/app/runtimes.json` описывает ожидаемые размеры и SHA подготовленных `payload/chrome.zip`, `payload/edge.zip` и `payload/brave.zip`. Источники браузеров перечислены в `windows/Browser-sources.txt`. В частности, оригинальная загрузка Edge указана как MSI, а Windows-установщик ожидает уже подготовленный ZIP. Переименование MSI в ZIP не создаёт нужный payload.

Наличие браузера в тестовом macOS-кэше также не заменяет Windows-payload. Поддержка Gemini в Windows 0.13.1 не заявляется; её перенос должен пройти отдельную проверку.
